# 버디아코니아 지역 경험 발견형 서비스 파일럿 v0.1
작성: 2026-10-15
상태: 기능 시연용 브랜치 / 운영 검토 필요
관련 이슈: #36

## 목적
댕스카우트의 오프라인 미션 → 셀프 체크 → 참여 기록 → 보상 모티브를 참고하되, 반려견 스카우트 브랜드·디자인이나 콘텐츠를 복제하지 않는다.
버디아코니아 소비자가 지역 경험과 혜택을 **발견하고, 관심을 저장하고, 직접 참여할 이유를 찾는** 서비스 기능을 만든다.

## 현재 포함된 기능
- /discover 에서 기획 중인 경험 5개 탐색
- 여행·체류 / 봉사·미션 / 지역 발견 / 배움·관계 카테고리와 텍스트 검색
- 관심 경험 저장과 필터링 (개별 브라우저의 localStorage)
- 경험 상세, 준비 단계, 예상 지역·형태 및 현재 미확정 상태
- 3개 미션 체크리스트, 체크 진행률, 체험 완료 표시 (공식 참여·인증 아님)
- 참여자가 경험 제안을 작성해 **로컬 초안으로만 저장**하는 기능
- 공개 홈페이지에서 /discover 진입

## 현재 제공하지 않는 기능
- 신청·예약·결제·환불, 실제 상점 혜택, 미션 인증, QR/NFC 출석, 공식 와펜 및 수료증
- 로그인·계정 간 동기화, 데이터베이스 영속 저장, 운영자에게 경험 제안 전송
- 실시간 행사 일정, 실제 판매 상품·가격, 승인된 협력 기관·사업자 정보

## 데이터와 개인정보
- 카탈로그는 공개 가능한 *가상 파일럿 콘텐츠*로 작성했다. 실제 행사를 판매하는 것이 아니다.
- 로컬 기록은 브라우저에만 남는다. 시크릿 모드, 브라우저 데이터 삭제 및 다른 기기에서는 사라질 수 있다.
- 개인정보 입력을 유도하지 않으며 제안 폼에 개인정보를 쓰지 말라고 고지한다.
- 실서비스에서는 개인정보와 거래 데이터를 인증·권한 통제된 Core 저장소로만 관리한다.

## 향후 Core 이벤트 설계 (아직 구현되지 않음)
1. EXPERIENCE_PUBLISHED: 검증된 제휴처/운영자만 게시 승인
2. EXPERIENCE_SAVED: 관심 저장 (동의된 계정에 한해)
3. PARTICIPATION_REQUESTED: 참가 신청과 비용 조건 명시
4. PARTICIPATION_APPROVED: 정원 및 운영자 승인
5. MISSION_EVIDENCE_SUBMITTED: 현장 검증 자료 제출
6. MISSION_VERIFIED: 검증 담당자 승인
7. BENEFIT_GRANTED: 계약된 실제 혜택 지급
8. TRANSACTION_RECONCILED: 사업비 및 운영비 정산·감사기록

참여자가 등록한 경험은 경험 작성자, 운영자 승인, 공개 조건, 비용, 환불, 안전 검증을 별도 관리한다.
미션 체크와 공식 인증은 반드시 분리하며, 공식 적립은 검증된 활동의 고유 Event ID로 멱등 처리한다.

## Toss 미니앱 연동
- Toss SDK와 앱인토스 관련 권한·심사를 확인한 뒤 네이티브 라우팅, 로그인, 결제·알림 흐름을 설계한다.
- QR은 일반 링크부터 테스트 가능하나 **현장 인증 신뢰성 확보**에는 별도 서버 검증이 필요하다. NFC 직접 인식은 지원 여부를 검증하기 전까지 제공한다고 주장하지 않는다.
- 소비자 UI는 공개 사이트와 Toss에서 공유할 수 있지만 결제·개인정보·인증 정책은 각 채널의 규칙을 따른다.

## 검수 항목
- 모바일 360~430px / 태블릿 / 데스크톱 레이아웃
- 검색 필터, 관심 저장·해제·필터, 새로고침 시 복원
- 다른 경험 선택 시 미션 상태 분리, 체크/체크 해제, 진행률
- 경험 제안 초안 저장/삭제, 개인정보 입력 주의 문구
- 검색 결과 없음 상태, 필터 초기화
- 공개 화면에 실거래/공식 인증 오해 소지가 없는지 확인
- 기존 / 및 /ops 영향 없이 빌드 통과, Vercel Preview URL 검증
