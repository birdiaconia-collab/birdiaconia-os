# HWPX 문서 실행실 v0.1 — 실사용 테스트 브랜치

## 목표

기존 HWPX 양식 → 변수 또는 빈 표 셀 입력 → 새 HWPX 저장 → 다시 열어 구조 검증하는 최소 실동작 도구다. 기존 Birdiaconia `/ops` 하위 `/ops/documents`에 추가하며 Site 및 Toss를 하나로 합치지 않는다.

## 범위

- **가져오기**: `HWPX` ZIP 문서만 지원. 바이너리 `.hwp`는 지원하지 않는다.
- **자동 변수**: `{{성명}}`, `{{날짜}}` 등 문서 안의 이름을 인식하고 값을 적용한다. 한 문단 안에서 여러 텍스트 런으로 갈라진 변수도 처리한다.
- **기존 문구 치환**: 문단의 특정 문구를 사용자가 명시적으로 지정해 바꾼다.
- **빈 표 셀 입력**: 표 내부에 텍스트 런이 있거나 `<hp:t/>`가 있는 빈 셀에 값을 입력한다. 셀 번호는 XML 순서이며 문서의 눈에 보이는 순서와 다를 수 있다.
- **내보내기**: 새 이름 `_작성본.hwpx`로만 다운로드한다. 원본 덮어쓰기는 없다.
- **검증**: 다시 ZIP을 열고 CRC32, 항목 목록 동일성, 각 섹션 XML 파싱 가능 여부, 원본 부속 파일 바이트 동일성, 표 개수 동일 여부를 검사한다.
- **보안**: 파일과 개인정보는 브라우저에서만 처리한다. 서버 업로드, 자동 저장, 공유, AI 제공자 전송은 없다. 25MB 입력 제한, 100MB 압축 해제 상한, 1,200개 항목 제한.

## 한계 / 개발 후 추가할 것

1. HWPX 조판 렌더러가 아니므로 한컴오피스에서 표 높이, 페이지 경계, 줄바꿈은 **반드시 육안 검수**한다.
2. HWP 바이너리, DOCX, XLSX, PDF 편집은 현재 지원하지 않는다.
3. 복잡한 `hp:tc` 중첩 셀, 스타일 선택, 텍스트 런이 없는 셀은 일부 미지원이다.
4. 문서 안에 `{{변수}}`가 없으면 자동 매핑이 불가능하므로 문구 교체 또는 빈 셀 직접 입력을 쓴다.
5. Core 영속 저장, 행위 승인, 사용자 로그인 및 접근 권한은 이 구현에 연결하지 않았다. 개인정보가 포함된 문서는 공유 기기에서 사용하지 않는다.
6. 실제 복지관 HWPX 서식을 익명화한 후 레이아웃·문자 인코딩·내장 이미지 보존 회귀시험을 진행해야 한다.

## 확인 방법

1. Preview 배포의 `/ops/documents`에 들어간다. (운영/main 배포는 변경하지 않는다.)
2. 임의의 테스트 HWPX 문서에 `{{성명}}` 필드를 넣고 가져온다.
3. 변수를 입력하거나 빈 표 셀을 채운다.
4. `HWPX 작성본 저장`을 누른 뒤 성공·미입력 변수·부속 항목 검증을 확인한다.
5. 새 파일을 한글 프로그램에서 열고 원본 파일과 조판을 비교한다.

## 로컬 단위 테스트

`npm test`는 `lib/hwpx-workbench.ts` 엔진의 HWPX 가져오기 / 치환 / 저장 / 재검증을 테스트하며 원본 데이터 대신 테스트 코드에서 생성한 합성 HWPX를 사용한다. 테스트에서 실사용 개인정보는 쓰지 않는다.
