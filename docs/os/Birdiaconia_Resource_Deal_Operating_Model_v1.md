# 버디아코니아 통합 자원 조달·협상·원가·정산 운영 기준 v1.0

상태: 검토용 / 2026-10-21 / **운영 Vercel 및 Toss 배포 금지(명시적 컨펌 종료 후 별도 승인)**

## 1. 확정된 사업 방향
- 버디아코니아의 조직 형태는 **일반협동조합**을 기본으로 설계한다. 실제 법인 설립과 사업자등록은 별도 절차다.
- 임대·숙박·공간·체험·여행·돌봄·유통·플랫폼 등 다양한 사업을 검토하되, 업종별 허가·신고·면허 의무를 면제하는 것으로 해석하지 않는다.
- 직접 소유보다 **자원별 구매, 임차, 네고, 할인, 무료사용, 현물후원, 교환, 공동운영, 위탁, 매출·수익배분** 등 조건별 계약을 우선 설계한다.
- 현금 지출이 없는 무상자원을 실제 현금 원가로 잡지 않는다. 비교용 기준가나 현물추정액은 별도 필드에만 기록한다.

## 2. 모든 자원에 공통 적용
장소/부동산/숙박, 차량/운송, 인력/강사/돌봄, 음식/식재료, 물품/장비, 농산물/상품/위탁판매, 교육·관광·지역체험, 소프트웨어/플랫폼·결제, 기타 서비스.

한 자원은 특정 공급자와 하나의 고정가로 묶지 않는다. 동일 자원을 회차마다 서로 다른 공급처·가격·제공방식·예약취소 조건으로 확보할 수 있다.

## 3. Core 데이터 저장 위치
Core Storage v1: https://docs.google.com/spreadsheets/d/1j8QLvpC_-qnxydBrqITaRV8vqnxl-3AZfpK8cUq3eUM/edit

기존 시트 유지:
- `Resources`: 자원 마스터(정본), 소유자·관리자 키
- `Projects`, `Events`: 프로그램·회차
- `Transactions`: 실제 금전 거래(출납 정본). 사용 기록과 구별

2026-10-21 신설:
1. `Resource_Partners`: 공급자/협력처 (사업자 정보/적법 운영상태/접근성/연락정보 참조키)
2. `Resource_Offers`: 협상 전후 금액, 제공방법, 현물참고가, 사용·취소 조건, 인허가 상태
3. `Resource_Agreements`: 담당자 승인, 계약/승낙서, 수익배분 기준, 계약 상태
4. `Resource_Usage`: 회차 실사용, 사용수량, 실제 비용, 지급거래 `transaction_id` 참조
5. `Program_BudgetLines`: 회차별 계획 현금원가 및 참고 현물가
6. `Program_Pricing`: 참여 예상 인원, 현금원가, 지원금/후원금, 목표 잉여금, 제안 참가비·승인 참가비 분리
7. `Resource_Codes`: 모든 유형과 상태의 정의

## 4. 계산과 회계
- `Resource_Offers`의 견적/합의/지급예정은 `Transactions`의 실제 지출과 별개의 상태다.
- `Resource_Usage`와 `Transactions`의 실제 금액을 대조하고 지급 건을 중복 계상하지 않는다.
- 무상/현물 지원은 현금원가 **0**. 교환·수익배분은 거래 실질에 따라 별도 세무 검토.
- 보조금과 후원금, 참가비 재원별 정산을 분리하며 중복 정산을 금지한다.
- `Program_Pricing` E/J/K는 수식으로 계획 자원 현금원가 → 필요한 참가비 매출 → 1인 제안금액을 계산한다. 최종 가격 승인 값은 운영자가 수동 입력한다.
- 가격 수식은 사업 검토 도구일 뿐, 세금·환불·수수료·위험 충당에 대한 충분한 수익성 판단을 대체하지 않는다.

## 5. 운영 프로세스
1. 사업·회차 선택(`Projects`, `Events`)
2. 자원 조회/신규 등록(`Resources`)
3. 협력처 확인(`Resource_Partners`)
4. 조건 제안 및 네고(`Resource_Offers`)
5. 자격/안전/인허가/시설 용도 및 사전 승인 확인
6. 계약·무상사용 승낙·후원 확인(`Resource_Agreements`, 승인 필수)
7. 회차별 자원 확정, 예산(`Program_BudgetLines`) 및 가격 승인(`Program_Pricing`)
8. 사용 사실 확인(`Resource_Usage`)
9. 대금 지급/환불 등 실제 거래(`Transactions`)와 증빙 연계
10. 정산, 실적 및 성과 기록. 한 번 확인한 정보는 고유 ID로 재사용

## 6. 통제
- 숙박·여행·운송·식품·돌봄 등은 운영/중개/패키지 판매의 형태와 관계없이 해당 법령 요건을 별도로 검토. **무상·프로그램비 포함이라고 등록·신고가 면제되지 않는다.**
- 계약, 송금, 환불, 외부 공개, 민감정보 전송에는 사람 승인. 수집되지 않은 승인·계약·입금 사실을 생성 금지.
- 협력처의 개인 연락처 및 민감정보는 제한된 저장소에서 관리하고 공개 GitHub/사이트/토스에 게시하지 않는다.
- 테스트·시뮬레이션 데이터는 실제 거래와 구분하고 라이브 Core에 가짜 데이터 등록 금지.
- Site와 Toss는 별도 채널로 유지한다. **생산 배포·Toss 심사/게시·법적 계약·외부 송금은 여기서 수행하지 않는다.**
